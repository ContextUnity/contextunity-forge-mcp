# Forge MCP and CLI tool catalog

Use the active server registry and schemas as the final authority. This catalog is a compact navigation aid; repository-specific behavior and current schemas belong in that repository's reference docs.

## Task lifecycle

- `task_list(worktree?, repository?, milestone_ref?, milestone_status?, status?, stage?, detail?, limit?, offset?, generation?)` lists tasks; defaults to ready tasks in the unique active milestone in the selected workspace. No active milestone returns an empty page; multiple active milestones require an explicit selector/status. `limit` is 1–100 (default 30); a nonzero `offset` requires the previous task-view `generation`. That token binds workspace, filters, and task/subtask state, independently of the code index. Byte trimming keeps whole tasks and subtasks and reports actual pagination. `milestone` aliases `milestone_ref`; `parked` selects work waiting for a scope owner, and `cancelled` selects retained cancelled tasks.
- `task_claim(task_id, stage, worker_id, worktree, bundle?)` claims the current gate and returns its guidance/context. `task_submit(task_id, stage, action, evidence, findings?, worktree?)` submits claim-bound proof or review findings; its optional MCP routing selector does not change evidence identity.
- `task show TASK_ID` aliases `task inspect TASK_ID`. Inspect and submit accept `--task TASK_ID`; sync accepts `--file PATH`. Use `task list --detail compact|full`; `--full` is supported but cannot be combined with `--detail`.
- `task_manage(action="verify", task_id, test?)` observes claim-bound proof without advancing; submit consumes that observation. Subtask actions are `subtask_add`, `subtask_update` and `subtask_list`. Delivery permits completed or cancelled slices; completed requires nonempty evidence. The stored evidence string is not independent execution proof.
- Headless CLI entry points are `task run TASK_ID --in-place`, `milestone run ID --in-place --target-base BASE`, `plan [list|show|run]` (run supports `--in-place`), and `workflow [list|show|run]`. Plans use active-tree snapshots without automatic branch commits; taskless workflows use `save: none`. Persistent autonomous workflow logging remains planned. Milestone operations also include `init`, `list`, `show`, `verify`, `handoff-context`, `handoff` and `db-recover`; they remain CLI-only.
- `task_blackboard` posts, reads, or inspects `draft`, `notes`, `findings`, `blockers`, `decisions`, and `deferred` at milestone, task, or subtask scope. `gate` filters or targets posts/reads. `decisions` and `deferred` are copied with topic labels to delivery `architectural_notes`.
- Task results default to Markdown; request MCP `format: "json"` or CLI `--format json` when parsing values. Context Markdown retains profile guidance and task evidence; truncated blocker summaries include an inspect recovery.

## Discovery and search

All 20 MCP tools accept a `worktree` selector. It is optional except for `task_claim` and `task_manage(action="next")`, which require it for task affinity; this includes task, guide, and checkpoint tools. Without a selector, keep the canonical server root regardless of active claims. Use `worktree: "."` to select that root. An absolute path or a relative path containing a separator selects an existing directory directly; a missing explicit path returns `WORKTREE_NOT_FOUND`.

Relative path selectors are rooted at the server root.

Otherwise, search canonicalized and deduplicated Git-registered worktrees and immediate `.worktrees/` children in this order: exact directory name; literal prefix or pure-digit milestone prefix with leading zeroes removed; literal suffix; literal substring. The first nonempty tier must be unique. Multiple candidates return `WORKTREE_AMBIGUOUS` without falling through to a lower tier; no match or an empty selector returns `WORKTREE_NOT_FOUND`.

A selected worktree supplies its adapter/configuration, code index, milestone manifests, and checkpoints. Git-linked worktrees share the task database through existing task-store resolution; standalone repositories remain independent unless explicitly configured to share a store. MCP requests do not transmit the client's current directory. These human-friendly aliases are MCP-only: CLI queries choose a workspace with `--root`, and CLI task claim/next operations use an existing `--worktree` directory path.

On universal-routing servers, selection resolves a request-local root, adapter, and index before typed dispatch. Use `"."` for the server root or an existing absolute/server-relative directory path. Name lookup takes the first nonempty tier: exact name, literal or normalized numeric prefix, literal suffix, then literal substring. Multiple canonical candidates fail with `WORKTREE_AMBIGUOUS`; empty values, missing paths, and unmatched names fail with `WORKTREE_NOT_FOUND`. Omission retains the canonical server root, never an active claim's root. Git-linked worktrees still share the task database through existing `tasks_db` configuration. MCP requests do not transmit client cwd. CLI global `--root` (or its environment/current-directory default) selects a checkout; claim/next `--worktree` takes an existing affinity directory path, not the MCP alias cascade.

For efficient navigation, confirm workspace and coverage with overview, reuse sufficient search previews, inspect one declaration, and explain only when relation edges are needed. Use `forge_read(selector)` for complete symbol bodies when previews are insufficient. Triage docs with `search_docs(query="...", include_excerpt=true)` and inspect `get_doc(path_or_id, detail="compact")` outlines before reading selected sections with full content. Exact `code_map_tests` call paths are verified test relationships; possible calls and lexical suggestions are not. Removal analysis is indexed static evidence, not runtime-safety proof. Lint reads stored syntax diagnostics; cycles are opt-in.

- `code_map_overview(aspects?, worktree?, limit?, offset?, detail?, generation?)` returns workspace root, components, counts, language coverage, profiles, and persisted primary/linked `coverage_by_workspace`. Database aspects are `counts`, `components`, `languages`, `coverage_by_workspace`, `cycles`, `compiled_profiles`, and `metadata`; adapter facets are `discovery`, `manifest_components`, `documentation_hubs`, and `milestones`. Omitted/empty aspects include all database aspects except opt-in `cycles`, plus adapter facets. Unknown aspects fail with the accepted set.
- `code_map_search(pattern, kind?, path?, exact?, include_docs?, include_preview?, group_by_file?, worktree?, detail?, limit?, offset?, generation?)` returns eligible exact name/qualname matches alone when present by default, otherwise ranked FTS/prefix results. `query` aliases `pattern`; `exact=true` requires an indexed exact name/qualname; `pattern="*"` needs a path or kind scope. Empty `path` is unfiltered. Results include signatures and `inspect_selector`; previews cover at most three hits, automatically for up to three total hits or on request for larger sets.
- `ast_grep_search(pattern, language?, path?, worktree?, detail?, limit?, offset?, generation?)` uses Tree-sitter `$NAME` and `$$$ARGS` captures. Supply `language` when `path` is a directory or omitted; omit it only with a recognized file extension. Use a compiled profile ID from `code_map_overview`. CLI: `contextunity-forge-mcp ast grep --lang rust --path file.rs 'PATTERN'`; CLI `--lang` is required.
- `search_docs(query, doc_type?, component?, include_excerpt?, worktree?, limit?)` searches indexed docs, guides, and ADRs. Use `search_docs(query="...", include_excerpt=true)` for match-centered triage; `component` filters documentation components or directory prefixes (`code_map_search` uses `path`). Use `get_doc(path_or_id, detail="compact")` without `section` for an outline, then `get_doc(path_or_id, section="...")` for an exact section title and full content by default.

## Inspection and hierarchy

- `code_map_inspect(selector, worktree?, include_coverage?, show_doc?, show_source?, leading_lines?, max_body_lines?, source_offset?, generation?)` returns symbol summary, receiver metadata, exact callers/callees, verified `documented_in`, compact governing invariants, paged `analysis_gaps`, and candidate dispatch targets (`possible_calls`). Inspect Markdown shows one document page per citation; JSON retains its structured pages.
- `forge_read(path?, selector?, mode?, start_line?, line_count?, pattern?, regex?, context?, baseline?, output_file?, worktree?)` reads text without an index in core modes (`lines`, `raw`, `search`, `delta`). Markdown `outline` requires docs; code `outline` and symbol `snippet` require codemap. Active task claims add write-scope badges. Conditional 1–3 line Hints use only confirmed graph/task signals and enabled tools. CLI parity: `contextunity-forge-mcp read <path> --mode <mode>`. Sensitive gitignore-style patterns block input and export destinations; paths reject traversal and symlinks.
- `forge_read(selector, worktree?, leading_lines?, max_body_lines?, source_offset?, generation?)` returns the complete digest-verified symbol when its serialized response fits the configured byte limit; otherwise it pages at complete source-line boundaries. It defaults to 5 leading lines plus the complete symbol and honors an explicit smaller body-line limit normalized to at least one. Every nonzero `source_offset` requires the previous page's explicit `generation`, even within one MCP session. Missing or stale tokens return a restart hint. An individually oversized line returns a budget error, not a partial line. Collection pagination also requires its generation.
- `code_map_explain(selector, direction?, worktree?, include_coverage?, show_doc?, show_source?, leading_lines?, max_body_lines?, source_offset?, generation?)` returns endpoint IDs, query-relative direction, ownership, invariants, and candidate dispatch; full detail includes stored edge evidence. Every nonzero source or collection offset requires the previous page's explicit generation. Inspect and explain retain configured 5-leading/200-body preview defaults and 1..500 body-line bounds. Explain retains its own `documents` page.
- `code_map_impact(selector?, changes?, direction?, depth?, worktree?, detail?, limit?, offset?, generation?)` traces inbound dependencies (default; exact `calls` and candidate `possible_calls`) or outbound dependencies, or accepts exactly one Git `changes` mode: `staged`, `unstaged`, or `head`. Depth-one non-seed nodes include selected edge endpoints, direction, location, and confidence. Change continuations bind graph and captured snapshot; inspect `unmapped_changes` and `complete`. A range maps only when its selected postimage matches the indexed file.
- `code_map_tests(selector, direction?, worktree?, detail?, limit?, offset?, generation?)` follows exact call paths from `test_case` roots or from tests into production. Helpers/fixtures may be path nodes, not roots. Bounded inbound lexical suggestions lack `call_path` and do not prove coverage.

## Verification and utility

- `code_map_prove_removal(selector, worktree?)` considers static references and blocks removal for candidate callers (`possible_calls`).
- `code_map_analyze(target, worktree?, lint?, include_cycles?)`: empty target means workspace diagnostics; a path means scoped diagnostics with digest-verified snippets/reasons where known. An unindexed non-empty path fails with `PATH_NOT_INDEXED`; indexed scopes with no diagnostics remain successful. `diagnostics` and `cycles` mode errors remain specific. Exact Markdown/MDX targets can include paged `doc_diagnostics` (`broken_doc_link`, `dead_doc_symbol`, `stale_doc_sections`); suggestions are not verified links. It also reports paged declared-public symbols unreachable from indexed test cases by exact calls. `lint=true` reads stored syntax diagnostics; `include_cycles=true` opts into cycles.
- `code_map_query(operation, selector?, target?, level?, min_lines?, worktree?, include_coverage?, depth?, limit?, offset?, generation?)` returns graph slices, unwired nodes, implementations, untested symbols, code clones/duplicates (`operation="duplicates"`, `level="symbol"|"file"`, `min_lines=10`), or read-only SQL. Use `code_map_query(operation="sql", selector="SELECT ...")`, placing one read-only SELECT/WITH statement in `selector`. Use `code_map_query(operation="duplicates", target="src", min_lines=10, level="symbol")` to find exact or near duplicate functions/methods with actionable refactoring suggestions.
- `session_checkpoint(action, name?, content?, worktree?)` manages JSON state in the selected task-store project's SQLite checkpoints by full gate breadcrumb.
- `forge_guide(topic?, force?, worktree?, format?)` defaults to `query`; its `topics` index advertises enabled `lifecycle`, `acdd`, `gates`, `subtasks`, `code`, `docs`, `ast`, `adapter`, `init` and `validate` topics. CLI: `guide TOPIC`. Shared CLI/MCP guidance retains JSON keys and uses Markdown by default; select JSON explicitly for parsing. Known disabled topics return `{}`; blackboard instructions disappear when that module is disabled. Follow the active profile and claim `workflow_guidance`; example gate names grant no authority. In the Forge repository, see `docs/reference/mcp-tools.md` under Built-in guide.
- Selector forms include canonical node IDs; paths (`src/scanner.rs`, also stripping `file://`, `file:`, `./`); path+symbol (`src/scanner.rs:scan`); and path+line (`src/scanner.rs:42`, `src/scanner.rs#L42`, innermost node). Ambiguous bare names return candidates and never hijack to modules. `.md` selectors route to `get_doc` or `search_docs`.

## Documentation and invariant graph

Admitted Markdown/MDX, including milestones and plans, is indexed with section locations and frontmatter status. Confined relative links/wikilinks create `cites_doc`/`cited_by_doc` only when one section resolves. Documentary code claims are eligible in the source document's workspace unless an explicit normalized file path confines them elsewhere. Document, invariant, and component nodes do not verify claims. In each eligible claim occurrence, the first non-empty tier wins: exact normalized qualified name (`::` and `.` equivalent), exact declared name, then qualified-name segment suffix. Only one target in that tier creates a verified `referenced_symbols` relation; lower tiers are not combined.

Full `get_doc` pages ambiguous winning-tier `referenced_symbol_candidates`, each with source claim (`doc_id`, path, name, line) and target identity (`id`, name, qualname, kind, path, line). Candidates are navigation only: they create no `documents`, `references_doc`, `governs`, or `governed_by` edges and do not establish verified coverage. Compact detail omits candidate data and emits its full-detail hint once; MCP and CLI `docs get` default to full content. Its verified `referenced_symbols` rows retain the citing `doc_id` and `citation_line` separately from the target declaration's `line` and URI. Inspect exposes verified `documented_in` citations with `doc_id`, citation `line`, document-section `doc_line`, and a resolved document URI; full Markdown shows each section's content once. Explain retains its separate `documents` page. Impact exposes `affected_docs`, including a retained source-file claim after declaration deletion.

`INV-*` declarations become invariant nodes; `governs` requires a uniquely resolved code claim within the invariant node's line span. An explicit normalized source-file target confines resolution; an unscoped claim uses the document's workspace and the same uniqueness rule. Inspect, impact, and task context show at most five direct rules and five one-hop IDs with source locations and omitted counts. Suggestions, ambiguous candidates, and token similarity do not prove governance. This projection supplements, never replaces, task invariants, profile guidance, decisions, commands, or proof receipts.

Archived milestones under `docs/milestones/archive/` (including linked-workspace paths) are excluded from default documentation search and hubs. An explicit archive `component`/`path` enables search; `get_doc` remains available. Archives emit no `documents`, `references_doc`, `governs`, or `governed_by` edges.

### SQL columns and joins

The SQL schema is `nodes(node_id, id, kind, name, qualname, path_id, line, end_line, is_test, language, generated, details, node_hash, owner_path_id)`, `path_dictionary(path_id, path)`, `edges(src_hash, kind, dst_hash, path_id, line, evidence_id, confidence_id, occurrence_count)`, `files(path, status, digest, size, language, is_test, generated, path_hash)`, and `doc_sections(doc_id, path, section_title, doc_type, content, invariants, referenced_symbols, is_invariant)`. Paths and endpoints use integer IDs/hashes; there are no compatibility views or `nodes.path`, `edges.src`, or `edges.dst` columns.

```sql
SELECT n.name, p.path, n.line
FROM nodes n JOIN path_dictionary p ON p.path_id = n.path_id
ORDER BY p.path, n.line, n.id;

SELECT src.name AS source, e.kind, dst.name AS target
FROM edges e
JOIN nodes src ON e.src_hash = src.node_hash
JOIN nodes dst ON e.dst_hash = dst.node_hash
ORDER BY src.id, e.kind, dst.id;
```

Missing-table or missing-column SQL errors retain the SQLite error and append a schema hint.
